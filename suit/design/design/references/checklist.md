# Design checklist

Usar antes de dar por cerrado un viewport o una página.

## First viewport

- [ ] Se lee como una composición (no dashboard accidental)
- [ ] Marca visible a nivel hero
- [ ] Un headline + una frase de apoyo + CTA group
- [ ] Imagen/plano dominante edge-to-edge (si es landing)
- [ ] Sin overlays tipo badge/chip sobre el hero
- [ ] Sin stats, schedules ni promos secundarias

## Page body

- [ ] Cada sección tiene un solo job
- [ ] Cards solo si hay interacción real
- [ ] Tipografía expresiva (o la del design system del repo)
- [ ] Fondo con atmósfera (no flat único sin intención)
- [ ] Ancla visual real (producto/lugar/contexto)
- [ ] 2–3 motions con propósito
- [ ] Sin clutter (pills, icon rows, boxed promos)
- [ ] Tokens de color definidos; sin AI-slop defaults
- [ ] Desktop + mobile OK

## Exception

Si el proyecto ya impone un sistema visual, seguir ese sistema y anotar qué reglas de este checklist se flexibilizaron y por qué.
